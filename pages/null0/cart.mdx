<Callout emoji='👾'>Games are called *carts*, like cartridges for old console systems.</Callout>

A cart is a zip file with `main.wasm` at the root, plus whatever assets you ship with it. The host loads that wasm, hands it the [null0 API](/null0/api), and calls back into it as the game runs. The extension is `.null0`, but it is an ordinary zip - go ahead and open one.

Here is one, now:

<Null0Cart src={`${CDN}/carts/demo_c.null0`} />

Your game is made of callbacks. You do not have to implement them all - the host skips any you leave out.

## lifecycle

Three callbacks bracket your game. In C-like pseudo-code:

```c
// called once, when the cart is loaded (in C, main() works too)
void load();

// called on every frame - this is where your game lives
void update();

// called when the cart is unloaded
void unload();
```

Each language spells these its own way. See [languages](/null0/languages) for yours.

## input

### buttons

Button input is mapped from [libretro keys](https://docs.libretro.com/guides/input-and-controls/). It helps to imagine every controller is an SNES pad: use `buttonUp`/`buttonDown` and your game works with a keyboard or a gamepad, for any player. When the event came from a keyboard, `player` is `9999`.

## files

Anything in the zip is readable, both through the [null0 image/sound/tilemap functions](/null0/api) and through ordinary WASI file calls. Put `logo.png` in your cart folder and `load_image("logo.png")` finds it.

Writes go to a per-cart save directory, so a cart can keep a high-score file without being able to touch anything else on the machine. There is no working directory - use absolute paths (`/save.txt`) if your language's file API wants one.

## running

The native runtime defaults to `main.null0`, but takes an argument:

```sh
null0 some_cart_directory
null0 some_cart.null0
```

A directory works as well as a zip, which is handy while developing.

## distribution

Ship the `.null0` and let players download [the runtime](https://github.com/notnullgames/null0/releases). Or name your cart `main.null0`, put it next to the runtime, and rename the runtime to your game.

You can also glue them into one executable:

```sh
# linux or mac
cat null0 mygame.null0 > mygame && chmod +x mygame

# windows
copy /b null0.exe+mygame.null0 mygame.exe
```

This is much the same as [how love2d does it](https://love2d.org/wiki/Game_Distribution).

For the web, the [templates](/null0/quickstart) already publish a playable page to github-pages on every push.
